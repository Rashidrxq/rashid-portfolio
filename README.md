# Muhammed Rashid PP — Portfolio

A React 19 + Vite portfolio with an editorial cream, charcoal, and red visual system. It includes a TypeScript customer-support chat widget backed by a local document index and an optional local Ollama model.

## Run the site and support API

Requires Node.js 20.19 or later (Node 22 is recommended).

```bash
npm install
npm run dev
```

Run the itinerary API contract tests with `npm test`. They mock OpenRouter and do not require a key or send requests to the provider.

The Vite site runs at `http://127.0.0.1:5173/`. The Express API listens on loopback port `3001`; Vite proxies `/api` to it so the browser uses same-origin URLs. `npm run dev` starts both processes. To serve a production build through Express:

```bash
npm run build
npm start
```

Express serves the generated `dist/` directory. For a site-only Vite preview, `npm run preview` is available, but the support API should still be running separately (`npm run start`) for chat replies.

## Support assistant modes

The chat widget works without a paid API or an Ollama installation. By default it retrieves relevant snippets from the local demo knowledge set and labels replies **LOCAL SOURCE EXCERPTS · NO MODEL**. When no note matches a question, it says it cannot confirm the answer and offers Rashid's email and phone links. No external AI provider is called.

For locally generated support answers, install and run [Ollama](https://ollama.com/), then pull a model. The defaults are `qwen2.5:3b` at `http://127.0.0.1:11434`:

```bash
ollama pull qwen2.5:3b
ollama serve
```

Copy `.env.example` to `.env` to override the model or loopback URL. These are server-only settings. The URL is restricted to a loopback host, no API key is used for support chat, and the browser never receives the model URL. The application does not install a model automatically; a missing model uses the extractive demo mode. Support chat has no paid provider fallback.

## Optional OpenRouter travel planning

The Travel Planner's **Build Starter Itinerary** button calls the Express endpoint `/api/itinerary`, which uses OpenRouter's OpenAI-compatible [chat completions API](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request) at `https://openrouter.ai/api/v1`. The model is fixed to [`google/gemma-4-26b-a4b-it:free`](https://openrouter.ai/google/gemma-4-26b-a4b-it%3Afree/pricing); the request disables provider fallbacks and does not switch to a paid model. Free endpoints can be rate-limited or unavailable, in which case the UI explains the error and lets the user retry. **Build Local Draft** remains available as a no-provider alternative.

Only submitting **Build Starter Itinerary** sends destination, dates, budget, currency, traveler count, pace, and interests to OpenRouter. Model output is structured JSON, validated on the server, then rendered in the itinerary panel. Cost and venue suggestions are estimates; this app has no live travel-data source. It must not be treated as current opening hours, schedules, availability, bookings, or prices. If the budget appears unrealistic, the plan flags it rather than claiming the trip fits.

Configure the server key locally:

1. Copy `.env.example` to `.env` (`cp .env.example .env`, or `Copy-Item .env.example .env` in PowerShell).
2. Replace `your_key_here` with your OpenRouter key in `OPENROUTER_API_KEY`.
3. Restart `npm run dev` or `npm start` so Express reads the new setting.

`.env` and `.env.*` are ignored by Git, with `.env.example` explicitly allowed. Never rename the setting to `VITE_OPENROUTER_API_KEY` or add the key to browser code. `/api/itinerary/status` reports only whether the key is configured. The endpoint validates inputs, limits requests to five per minute per IP, bounds model output, and never logs the key or trip content. Set `OPENROUTER_API_KEY` in the server environment when hosting; do not commit `.env`.

## Add knowledge sources

Place reviewed `.md`, `.txt`, or `.pdf` files in `server/knowledge/`. Files are indexed when the API starts; restart `npm run dev` or `npm start` after adding or changing a document. Markdown headings become section labels in source citations. Plain text and PDFs are also supported. The bundled `portfolio-faq.md` is explicitly a portfolio demo set, not a business policy document.

Index limits: 40 files, 8 MB per file, 32 MB combined, and the first 80 pages per PDF. Files outside `server/knowledge/`, symbolic links, and extensions other than Markdown, text, and PDF are not indexed. There is no document-upload endpoint.

Keep documentation factual and current. Do not add confidential details, credentials, unsupported prices, service levels, guarantees, or business policies. The assistant can only answer from retrieved notes and provides source labels generated by the server. Treat retrieved text and user input as untrusted; the local model prompt instructs the model not to follow instructions found in either.

## Privacy and security behavior

- Chat history exists only in React memory for the current page load. Closing and reopening the widget preserves it; **New chat** resets it. No cookies, localStorage, or database store the conversation.
- The support chatbot's only model adapter is local Ollama. Its text and documents are not sent to a paid provider.
- The travel planner calls only the selected OpenRouter free Gemma model after the user submits **Build Starter Itinerary**. The local planner makes no external calls, and there is no paid-model fallback.
- The API limits JSON bodies, question size, request rate, and indexed file size; validates same-origin browser requests; uses Helmet; and does not log message content.
- `/api/support/health` reports whether the configured local model is reachable and how many local notes were indexed. It does not return credentials or server URLs.
- Human support uses the portfolio's published `rashid.mhd.pp@gmail.com` and `+919745393044` contact links.
